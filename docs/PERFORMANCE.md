# 常驻性能检查（1.1.1）

检查日期：2026-10-27。针对长期运行时的 CPU 唤醒、日志 I/O、隐藏界面和资源释放进行优化。

## 已修复的开销

- 旧版每秒对最多 16 个日志检查两次属性并重新打开读取，每 5 秒递归扫描历史目录。新版以文件/目录变化通知驱动增量读取；未变化的日志不重新打开。
- 正常空闲不使用逐秒计时器。能够覆盖全部历史时每 5 分钟校准一次；超出监听范围或监听失败时每 30 秒校准，避免旧会话重新运行后一直未被发现。
- 运行中每秒只计算平均速率；显示出来的文本未变化时，不向主线程重复发送更新。
- 大量聊天正文、工具结果和已完成条目的正文不再完整解析成字典，只读取必要的事件头；未知格式保留完整解码作为兼容路径。
- 大日志行处理后释放较大的缓冲区；监控队列使用任务级自动释放池，避免临时对象积累。
- 弹窗关闭后卸载 SwiftUI 内容；测量视图只在打开/调整弹窗时临时创建，避免隐藏视图继续订阅更新和运行倒计时。
- 额度刷新计时器允许 6 秒容差，电脑休眠时停止计时器和日志监听，唤醒后重新同步。
- 最多保留 64 个候选日志、32 个会话解析器、48 个目录监听；监听描述符使用 close-on-exec，并在停止时关闭。目录历史索引也设置了数量上限。

## 同机隔离对比

使用本轮优化前的源码快照与新版，以相同输入在独立进程中比较，均使用 `swiftc -O`。不读取真实会话、不访问账户，也不发起模型请求。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 约 400 MB 等效大日志解析负载，CPU 时间 | 0.905 秒 | 0.0024 秒 |
| 2,000 个历史文件，预热后空闲 60 秒的 CPU 时间 | 0.556 秒 | 0.082 秒 |
| 同一次 60 秒空闲期间的主线程统计通知 | 60 次 | 0 次 |

空闲 CPU 时间约减少 **85%**。60 秒测试包含保底目录校准，不只统计无扫描的间隙。以上是隔离监控模块的测试结果，不代表整个应用的固定 CPU 占用，也不包含每分钟额度查询的子进程和网络开销。

## 完整应用的短时采样

弹窗关闭、工具常驻菜单栏时，对优化前后应用主进程分别采样 20 秒：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 20 秒内累计 CPU 时间增加 | 0.63 秒 | 0.04 秒 |
| 采样末 RSS | 117.2 MiB | 63.9 MiB |

新版采样时有 69 个数字文件描述符。两次会话活动不完全相同，仅作本机观察；不能据此推断固定耗电降幅。RSS 包含系统框架的共享页，也可能在首次打开面板后变化。该采样不包含额度查询子进程的 CPU。

## 回归验证

- 原有额度模型、RPC、错误与超时清理检查。
- 新任务开始、结束、取消和失败；运行时保留上一轮统计；多个任务不混算。
- 新建多级日期目录、原子替换日志、删除目录、临时目录的 `/var` 与 `/private/var` 路径别名。
- 文件通知不可用时的周期扫描降级。
- 未变化的日志连续检查不增加打开次数或读取字节数。
- 空闲时扫描、日志打开和主线程通知计数保持不变。
- 连续 25 次启动/停止后，打开的文件描述符没有持续增长。
- 弹窗尺寸、菜单栏切换、屏幕边界和圆角检查。

合计 176 项检查通过。这是短时回归与压力检查，尚未进行连续 24 小时的实机耗电或内存稳定性测试。

## 自行检查

```bash
bash test.sh
bash performance.sh
```

性能脚本默认进行约 60 秒空闲采样，可用 `CODEX_QUOTA_PERF_SECONDS=120 bash performance.sh` 延长。测试只创建并清理自己的临时文件；输出 CPU 时间、峰值 RSS 和通知次数，便于后续版本比较。不要将隔离解析进程的 RSS 当作完整菜单栏应用的内存占用。
